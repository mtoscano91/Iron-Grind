## Context

**GDD**: `design/gdd/networking-test-harness.md` — the harness (an observer that records what the server and client do, fault injectors for the transport and for server crashes, a zone configurator) exists for tests and development builds. `design/gdd/networking-wire-protocol.md` — message schemas, codecs and wire enums are what both sides share.
**Requirement**: none registered — the requirement is ADR-012's. `docs/architecture/tr-registry.yaml` is empty.

**ADR Governing Implementation**: ADR-012 Server/Client Assembly Boundary — Decision 3 (classification), Decision 4 (message schemas and the code that reads and writes them are `Foundation`), Decision 6 check 1 (every `Foundation` type is on the shared allow-list with a named client consumer, or on the not-yet-moved list), Migration Plan step 2 item 7.
**ADR Decision Summary**: last of the three Networking move stories (see Story 032 for the plan and the accepted classification). It moves the eight harness files that only tests use, and it ends the Networking step of ADR-012 by recording the 46 types that stay as shared: after this story no `IronGrind.Networking` type is on the not-yet-moved list.

**Decisions already taken with the classification (2026-10-08, accepted by the user):**
- The harness goes to `IronGrind.ServerLogic`, not to `IronGrind.DevHarness`: `DevHarness` is Editor-only and would remove the harness from development server builds, which its `#if UNITY_INCLUDE_TESTS || DEVELOPMENT_BUILD` guards are written to allow.
- `INetworkTestObserver` stays in `Foundation`: four shared files take it as an optional parameter. `PersistenceWriteReason` (declared in the same file), `SessionState` and `ZoneState` stay with it because the interface's method signatures carry them.
- Logic the GDD or the type's own doc comment says the client runs stays shared with a planned consumer, although no file in `src/Client/` uses it yet.

**Engine**: Unity 6.3 LTS | **Risk**: LOW — same pattern as Stories 032 and 033.
**Engine Notes**:
- All nine files of `TestHarness/` are wrapped whole in `#if UNITY_INCLUDE_TESTS || DEVELOPMENT_BUILD` (checked 2026-10-08: `#if` on line 1, `#endif` on the last line, one `#if` per file). The guard behaves the same in `IronGrind.ServerLogic`.
- Move each `.cs` with its `.cs.meta` with `git mv`. `src/Foundation/Networking/TestHarness/` and its `.meta` stay, holding `INetworkTestObserver.cs`.
- `src/ServerLogic/Networking/TestHarness.meta` is generated by Unity on the first refresh and must be committed.
- Verify by running the EditMode suite; read the total from `TestResults.xml` and check the run started after the new folder `.meta` was generated.

**Control Manifest Rules (Foundation layer → Server/client assembly boundary)**:
- Required: an entry is added to the shared allow-list only with its client consumer named in a comment beside it; "planned" marks a consumer that is not built yet.
- Required: namespaces do not change on a move; the story re-checks the reference graph and leaves the suite green.
- Forbidden: `InternalsVisibleTo` between production assemblies.

## Implementation Notes

1. **Re-check the graph.** Checked at story creation, 2026-10-08: outside `TestHarness/`, the harness type names appear in `src/Foundation/` only in a doc comment of `ConnectionSequenceCounter.cs` (already `<c>` text). Several `src/ServerLogic/` files mention them; that is the same assembly after the move.
2. **What the 8 files depend on**: `INetworkTestObserver`, `PersistenceWriteReason`, `SessionState`, `ZoneState` and other shared wire types, all of which stay in `Foundation` and are public. Their `using` directives are `System` and `System.Collections.Generic` only.
3. **Internals.** The harness classes have `internal` members (`RecordOutboundMessage`, `SignalStepReached`, the `TryConsume…` methods and others) that only test files call. The test assembly gets them through the `InternalsVisibleTo` that `IronGrind.ServerLogic` already grants. Re-check (second criterion) that no production file in `Foundation` calls one.
4. **Move**: create `src/ServerLogic/Networking/TestHarness/`, then `git mv` each of the 8 `.cs` files and its `.cs.meta` into it. Do not move `INetworkTestObserver.cs`, its `.meta`, or `src/Foundation/Networking/TestHarness.meta`. Do not edit the moved files.
5. **Comments for the five client-run types** (`SharedAllowList`):
   - `CycleTimerInterpolator` — `// consumer (planned): client cycle-timer display (its doc comment: client-render-oriented interpolation)`
   - `HeartbeatActivityTracker` — `// consumer (planned): client heartbeat sender (networking-wire-protocol.md CR-NET-7.10: heartbeats are client to server)`
   - `SelfDamageRecipientGuard` — `// consumer (planned): client self-damage handling (its doc comment: client-side recipient check)`
   - `SelfDamageSuppressionGate` — `// consumer (planned): client damage-number display (its doc comment: client-side suppression)`
   - `ZoneSnapshotReassemblyTracker` — `// consumer (planned): client zone-snapshot reassembly (networking-session.md: the client reassembles and gives up after the retransmit limit)`
6. **Lists** (`tests/EditMode/Architecture/AssemblyBoundaryLists.cs`):
   - Delete the whole "Networking" block of `NotYetMovedList` (header, the 55 remaining entries, and the blank line after it), so the list starts with "Currency".
   - Add the 46 entries to `SharedAllowList` as a new section after the Leveling group, introduced by `// Networking (ADR-012 Decision 4): message schemas, the codecs that read and write them, wire enums, and logic both sides or the client run.` and with one `//` sub-heading per group of the Part 2 table. Use full reflection names (`IronGrind.Networking.<Type>`); none of the 46 is generic.
   - The comment above `SharedAllowList`'s first group explains "planned"; it already covers these entries.
   - Do not edit `ServerOnlyNamespaces` (its doc comment already names Networking among the namespaces that keep shared types) or `AssemblyBoundary_tests.cs`.
