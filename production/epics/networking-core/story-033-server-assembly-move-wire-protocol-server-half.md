## Context

**GDD**: `design/gdd/networking-wire-protocol.md` — the server builds each client's per-tick packets: it filters what is relevant to a client (RFR-2), queues priority messages, batches and evicts under the bandwidth budget, tracks forced gold-sync delivery (MCR-4) and validates `SetTarget`. The client only reads what arrives, through the codecs.
**Requirement**: none registered — the requirement is ADR-012's. `docs/architecture/tr-registry.yaml` is empty.

**ADR Governing Implementation**: ADR-012 Server/Client Assembly Boundary — Decision 3 (classification), Decision 4 ("the message schemas and the code that reads and writes them are `Foundation`"; server-side handling is `ServerLogic`), Decision 5 (a `Foundation` member that `ServerLogic` needs becomes `public`), Decision 6 check 1, Migration Plan step 2 item 7.
**ADR Decision Summary**: second of the three Networking move stories (see Story 032 for the plan and the accepted classification). 13 of the 51 `WireProtocol` types are server-side packet assembly, queueing, buffering, filtering and validation; they move. The 38 message structs, codecs, wire enums, routing types and client-run helpers stay.

**The reading of Decision 4 used here** (accepted by the user with the classification): the three packet writers are server batching and eviction policy, not codecs. The code that reads and writes a message body is `BatchSubMessageCodec` and the other codecs, which stay shared; the writers call them.

**Engine**: Unity 6.3 LTS | **Risk**: LOW — same pattern as Story 032, plus one two-line visibility change.
**Engine Notes**:
- Move each `.cs` with its `.cs.meta` with `git mv`. `src/Foundation/Networking/WireProtocol/` and its `.meta` stay (38 files remain).
- `src/ServerLogic/Networking/WireProtocol.meta` is generated by Unity on the first refresh and must be committed.
- Verify by running the EditMode suite; read the total from `TestResults.xml` and check the run started after the new folder `.meta` was generated.

**Control Manifest Rules (Foundation layer → Server/client assembly boundary)**:
- Required: namespaces do not change on a move; the story re-checks the reference graph, deletes its entries from the not-yet-moved list and leaves the suite green.
- Required: if `ServerLogic` needs a member of a `Foundation` type, that member becomes `public`, or the type is in the wrong assembly.
- Forbidden: `InternalsVisibleTo` between production assemblies.

## Classification (ADR-012 Decision 3) — this story's 13 types

| Type (file of the same name) | Why it is server code |
|---|---|
| `RUBatchWriter`, `CycleBroadcastPacketWriter`, `PositionPacketWriter` | assemble one client's per-tick packet, with the eviction policy |
| `PendingSubMessage` | input to the batch writer and the relevance filter |
| `RelevanceFilter` | the server-side relevance filter (RFR-2) |
| ``PriorityPathQueue`1``, ``QueuedMessage`1`` | per-client server queue, flushed by the tick loop |
| `ClientBufferSet`, `ZoneBufferPool` | server-side per-client and per-zone buffers |
| `GoldSyncForcedDeliveryTracker` | per-client forced-delivery drop counter (MCR-4) |
| `SelfDamageEventDispatcher` | the one sanctioned place the server emits the event |
| `TargetSlotTracker`, `SetTargetOutcome` | server validation of `SetTarget`; the result follows its producer |

Source: the 2026-10-08 classification (doc comments and reference scans, not a reading of every method body).

The methods write a message body, which is codec work, so they belong in the shared codec.
3. **Move**: create `src/ServerLogic/Networking/WireProtocol/`, then `git mv` each of the 13 `.cs` files and its `.cs.meta` into it. Do not edit them.
4. **Doc comments in shared files that name a server type.** Sweep every file that stays in `src/Foundation/Networking/` for good (the 38 `WireProtocol` files, `TestHarness/INetworkTestObserver.cs`, `ZoneSnapshotReassembly/`, the five root files) and replace each `<see cref>` whose target is one of the 62 server types (this story's 13, Story 032's 40, and the 9 `TestHarness` types that move in Story 034) with `<c>…</c>` text. At story creation that is about 57 crefs in 16 files, the largest being `RUBatchCategory.cs` (12) and `BatchSubMessageCodec.cs` (8). Doing all 62 names now means Story 034 has no doc comments left to fix. Change nothing else in those files.
5. **Serialization checklist** — the grep of Story 032 covered the whole Networking folder and found nothing. Re-run it on the 13 files and say so in the completion notes.
6. **Lists** (`tests/EditMode/Architecture/AssemblyBoundaryLists.cs`): delete the 13 entries from the "Networking" block of `NotYetMovedList`; the generic two are written ``PriorityPathQueue`1`` and ``QueuedMessage`1``. Do not edit anything else in the file, and do not edit `AssemblyBoundary_tests.cs`.
7. **Tests**: no test file moves or changes. Tests reach `internal` members of the moved types through the `InternalsVisibleTo` that `IronGrind.ServerLogic` already grants.

Other rules:
- No performance impact expected — files change assembly only. The two methods' visibility does not change what runs.
