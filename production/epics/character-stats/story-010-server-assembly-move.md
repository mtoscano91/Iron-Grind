## Context

**GDD**: `design/gdd/character-stats.md` — the server owns every stat. Base values, equipment and buff modifiers, the transaction API and write ownership are enforced by the `CharacterStats` class; a client that could run or replace it could set its own stats.
**Requirement**: none registered — the requirement is ADR-012's (server-only code must not be compiled into a client player). `docs/architecture/tr-registry.yaml` is empty.

**ADR Governing Implementation**: ADR-012 Server/Client Assembly Boundary — Decision 3 (rule 2: "the `CharacterStats` class"), Decision 6 check 1 ("the not-yet-moved list … only shrinks … When it is empty it is removed"), Decision 7 (the stats view stays in `Foundation`), Migration Plan step 2 item 9 ("Character Stats (referenced by every other system; completes the stats view of Decision 7)").
**ADR Decision Summary**: Character Stats is the ninth and last system in the move order. Story 009 removed the last `Client` reference to the `CharacterStats` class. This story moves the six server types and, because the not-yet-moved list is then empty, removes the list and the test code that reads it. After it, every type in `IronGrind.Foundation` is on the shared allow-list with a named consumer.

**Engine**: Unity 6.3 LTS | **Risk**: LOW for the move (same pattern, tenth time). The edit to the boundary test logic is small but is the first change to three of its tests since they were written.
**Engine Notes**:
- Move each `.cs` with its `.cs.meta` with `git mv`. `src/Foundation/CharacterStats/` and its `.meta` stay (5 files remain).
- `src/ServerLogic/CharacterStats.meta` is generated by Unity on the first refresh and must be committed.
- The boundary test locates the `Foundation` assembly with `typeof(IronGrind.CharacterStats.EntityID).Assembly`; `EntityID` stays, so those lines are unaffected.
- Verify by running the EditMode suite; read the total from `TestResults.xml` and check the run started after the new folder `.meta` was generated.

**Control Manifest Rules (Foundation layer → Server/client assembly boundary)**:
- Required: namespaces do not change on a move; the story re-checks the reference graph and leaves the suite green.
- Required: every type in `IronGrind.Foundation` is on the shared allow-list with its client consumer named.
- Forbidden: `InternalsVisibleTo` between production assemblies.

## Classification (ADR-012 Decision 3)

`src/Foundation/CharacterStats/` (namespace `IronGrind.CharacterStats`) holds 11 types. 6 go to `IronGrind.ServerLogic`; 5 stay.

| Type | Destination | Rule |
|---|---|---|
| `CharacterStats` | `ServerLogic` | 2 — authoritative stat state (named by the ADR) |
| `StatSchema` (`internal`) | `ServerLogic` | 2 — the slot layout `CharacterStats` uses; used only by it and by tests |
| `ILevelingService` | `ServerLogic` | interface lives with its consumer (`CharacterStats` calls it; `LevelingService` implements it) |
| `BuffID`, `BuffModifierEntry`, `EquipmentModifierEntry` | `ServerLogic` | 4 — modifier bookkeeping with no production user outside the folder and no client consumer |
| `EntityID`, `ItemID`, `StatID` | `Foundation` | 3 — ids and the stat enum (on the shared allow-list since the test was written) |
| `ILocalPlayerStatsView`, `LocalPlayerStatChangedHandler` | `Foundation` | Decision 7 (Story 009) |

Because the namespace keeps shared types, `IronGrind.CharacterStats` is **not** added to `ServerOnlyNamespaces`.
