**What this story closes and what it leaves open.** It satisfies the first sentence of AC-CS-G-01 (check 1). The second sentence needs the client-binary scan (check 2), which is Damage Calculation Story 007 and needs a client build pipeline; AC-CS-G-01 is not fully closed until then.

## Classification (ADR-012 Decision 3)

`src/Foundation/Currency/` (namespace `IronGrind.Currency`) holds 7 types. 5 go to `IronGrind.ServerLogic`; 2 stay.

| Type | Destination | Rule |
|---|---|---|
| `CurrencySystem` | `ServerLogic` | 2 — the authoritative gold ledger (named by the ADR and by AC-CS-G-01) |
| `ICurrencyService` | `ServerLogic` | interface lives with its consumers (`LootAuctionService`, `LootTableService`, `ConnectionStateMachine`) |
| `GoldMutationResult`, `GoldMutationError` | `ServerLogic` | result types follow their producer |
| `GoldSyncEventArgs` | `ServerLogic` | 4 — the server-side event; the client receives the wire message `GoldSyncEvent` (shared, in Networking) built from it |
| `CharacterID` | `Foundation` | 3 — wire id (already on the shared allow-list) |
| `GoldTransactionReason` | `Foundation` | 3 — wire enum (already on the shared allow-list) |

Because the namespace keeps shared types, `IronGrind.Currency` is **not** added to `ServerOnlyNamespaces` (its doc comment already names Currency among the namespaces that keep shared types).
